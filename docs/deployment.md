# Развёртывание backend

## Быстрый старт

```bash
cp backend/.env.example .env      # правьте под себя
docker compose up -d --build
curl localhost:4000/health
```

Всё, что нужно менять перед первым запуском, — две переменные:

```bash
OFF_USER_AGENT="FoodLens/1.0 (ваша-почта@example.com)"   # обязательно
CORS_ORIGIN="https://ваш-домен"                          # если не только мобильное приложение
```

**Про `OFF_USER_AGENT`.** Open Food Facts просит каждого клиента представляться
и оставлять способ связи. Дефолтное значение с `contact@example.com` годится для
локальной разработки, но в продакшне это дурной тон и повод получить блокировку.

## Что где хранится

Состояние ровно одно — файл SQLite в томе `foodlens-data`:

| Что | Где | Потеря означает |
|---|---|---|
| История и избранное устройств | `/data/foodlens.db` | пользователи теряют всю историю |
| Кеш Open Food Facts | там же | лишние запросы к API, данные восстановятся сами |
| База добавок и цельных продуктов | в образе, `/app/data` | ничего: файлы неизменяемые |

Резервная копия — обычное копирование файла, но SQLite работает в режиме WAL,
поэтому копировать нужно через `.backup`, а не `cp`:

```bash
docker compose exec api node -e "
  const D=require('better-sqlite3');
  new D(process.env.DATABASE_PATH).backup('/data/backup-'+Date.now()+'.db');
"
docker compose cp api:/data/. ./backups/
```

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `4000` | порт сервера |
| `DATABASE_PATH` | `/data/foodlens.db` | файл SQLite; `:memory:` для тестов |
| `OFF_BASE_URL` | `https://world.openfoodfacts.org` | продакшн-хост Open Food Facts |
| `OFF_USER_AGENT` | заглушка | **замените**: требование Open Food Facts |
| `OFF_TIMEOUT_MS` | `6000` | таймаут одного запроса |
| `OFF_ENABLED` | `1` | `0` — полностью офлайн, штрихкоды перестают искаться |
| `CORS_ORIGIN` | `*` | сузьте, если API смотрит в интернет |
| `VISION_PROVIDER` | `none` | `google-vision` \| `clarifai` — распознавание продукта по фото |
| `OCR_PROVIDER` | `none` | `google-vision` — серверный OCR для клиентов без своего |
| `GOOGLE_VISION_API_KEY` | пусто | ключ для обоих провайдеров Google |
| `CLARIFAI_PAT` | пусто | токен Clarifai |
| `MAX_IMAGE_BYTES` | `8388608` | предел размера снимка после декодирования |

Провайдеры распознавания необязательны: со штрихкодом и OCR на устройстве
приложение работает без единого платного ключа.

## Устройство образа

Образ двухстадийный, и причина конкретная: `better-sqlite3` — нативный модуль,
которому для сборки нужны `python3`, `make` и `g++`. Держать компилятор в
рантайме незачем, поэтому сборка идёт в одной стадии, а в финальную переезжают
только `dist/`, продакшн-зависимости и файлы данных.

Обе стадии — `node:22-bookworm-slim`, это важно: нативный модуль собирается под
конкретную версию Node, и рассинхрон между стадиями сломал бы его при запуске.

Процесс работает от пользователя `node`, а не от root. `HEALTHCHECK` дёргает
`/health`, который читает базу добавок, — то есть проходящая проверка означает,
что данные загрузились, а не просто что процесс жив.

## Без Docker

```bash
cd backend
npm ci --omit=dev
npm run build        # нужны devDependencies; либо соберите отдельно и скопируйте dist/
NODE_ENV=production DATABASE_PATH=/var/lib/foodlens/foodlens.db node dist/index.js
```

Держите процесс под systemd или другим супервизором и положите перед ним
reverse proxy с TLS — сам сервер HTTP-only и терминировать TLS не умеет.

## Масштабирование

Сейчас это один процесс с файловой базой, и для приложения такого класса этого
хватает надолго: анализ — чистая функция без ввода-вывода, а единственный
внешний запрос (Open Food Facts) кеширован на неделю.

Когда одного процесса перестанет хватать, узкое место будет в SQLite при записи.
Порядок действий: сначала вынести кеш Open Food Facts в отдельное хранилище,
потом перевести `scans` на Postgres. Репозитории в `src/db/repositories.ts`
изолируют SQL, а движок анализа базы вообще не знает, так что менять придётся
один слой.

## Что не проверено

Dockerfile и compose написаны, но **образ в этом окружении не собирался**:
сетевая политика блокирует CDN Docker Hub, откуда тянутся базовые образы.
Проверено другое — ровно те же шаги без Docker: установка только продакшн-
зависимостей (нативный модуль собирается), запуск `dist/index.js`, та самая
команда из `HEALTHCHECK` (отвечает 200 и видит все 204 добавки) и реальный
разбор состава через продакшн-сборку.

Первый `docker compose up --build` стоит запустить у себя и убедиться, что
стадия сборки проходит.

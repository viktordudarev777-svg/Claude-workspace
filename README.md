# FoodLens

Мобильное приложение (iOS/Android), которое по фотографии продукта или по штрихкоду
объясняет простым языком, что внутри и стоит ли это брать.

```
Штрихкод  ─┐
Этикетка  ─┼─→  разбор состава  →  светофор + оценка 0-100  →  что делать вместо
Фото еды  ─┘     (добавки, БЖУ,        Nutri-Score               и чем заменить
                  Nutri-Score,
                  предупреждения)
```

## Что делает

**Три способа проверить продукт**

| Способ | Как работает | Точность |
|---|---|---|
| Штрихкод | Камера ловит EAN/UPC → Open Food Facts | самый надёжный |
| Этикетка | OCR состава на устройстве (ML Kit / Apple Vision), разбор на сервере | зависит от снимка |
| Фото продукта | Распознавание объекта (Google Vision / Clarifai) → база цельных продуктов | ориентировочная |

**Что показывает**

- **Светофор и оценка 0-100.** Каждый балл прослеживается до конкретной находки —
  движок возвращает разбивку «за что сняли».
- **Пищевые добавки.** 84 записи с уровнем риска, объяснением человеческим языком,
  допустимой суточной дозой, странами, где добавка ограничена, и ссылками на источники
  (EFSA, IARC, регламент ЕС 1333/2008, FDA, JECFA).
- **Пищевая ценность.** Светофор UK FSA по жирам, насыщенным жирам, сахару и соли —
  с порогами, а не просто цифрами. Плюс Nutri-Score (алгоритм 2022/2023).
- **Предупреждения.** Трансжиры, пальмовое масло, сахар в начале состава, избыток соли,
  признаки ультрапереработки, аллергены, отметки о ГМО.
- **Что делать.** Конкретные советы («поищите аналог без нитрита натрия»), а не оценки.
- **Чем заменить.** Продукты той же категории из Open Food Facts, пересчитанные
  **нашим же** движком — «лучше по той же мерке, что вы только что видели».

## Устройство

```
backend/          Node.js 20+ · TypeScript · Express · SQLite
  data/           E-добавки (по группам), справочник источников, цельные продукты
  src/domain/     Движок анализа — чистый, без сети, полностью покрыт тестами
  src/integrations/  Open Food Facts, распознавание объектов, серверный OCR
  src/routes/     HTTP API
  tests/          85 тестов

mobile/           React Native · Expo SDK 57 · TypeScript
  src/screens/    Сканер, Результат, История, Справочник, Настройки
  src/ocr/        OCR на устройстве с fallback на сервер
```

Ключевое решение: **`backend/src/domain/` не ходит в сеть и не знает про HTTP.**
Анализ — чистая функция от «состав + БЖУ» к вердикту. Поэтому он тестируется на
фикстурах, а не на живом API, и его можно без изменений перенести на устройство
для офлайн-режима.

## Запуск

### Backend

```bash
cd backend
npm install
cp .env.example .env      # значений по умолчанию хватает для локальной работы
npm run dev               # http://localhost:4000
npm test                  # 85 тестов
```

Проверка:

```bash
curl localhost:4000/health

curl -X POST localhost:4000/api/v1/analyze/label \
  -H 'Content-Type: application/json' \
  -d '{"text":"Состав: свинина, соль, фиксатор окраски Е250, усилитель вкуса Е621"}'
```

### Docker

```bash
cp backend/.env.example .env
docker compose up -d --build
curl localhost:4000/health
```

Перед первым запуском замените `OFF_USER_AGENT` на свой контакт — Open Food
Facts просит каждого клиента представляться. Подробности, резервное копирование
и переменные окружения — в [`docs/deployment.md`](docs/deployment.md).

### Мобильное приложение

```bash
cd mobile
npm install
npm start                 # Expo Dev Tools
```

На телефоне `localhost` — это сам телефон. Клиент это учитывает: если Metro раздаёт
бандл по локальной сети, адрес сервера берётся с того же хоста. Явно задать можно так:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.10:4000 npm start
```

**Про OCR на устройстве.** `@react-native-ml-kit/text-recognition` — нативный модуль,
в Expo Go его нет. Приложение это определяет само: без модуля снимок уходит на
сервер (`POST /analyze/photo`), с модулем текст распознаётся на телефоне и фотография
никуда не отправляется. Чтобы получить второй вариант, нужна dev-сборка:

```bash
npx expo prebuild && npx expo run:android   # или run:ios
```

## Данные и методика

| Что | Источник |
|---|---|
| Продукты по штрихкоду | [Open Food Facts](https://world.openfoodfacts.org/) |
| Оценки добавок | EFSA, IARC, [Регламент (ЕС) 1333/2008](https://eur-lex.europa.eu/eli/reg/2008/1333/oj), FDA, JECFA |
| Светофор по нутриентам | критерии UK FSA (front-of-pack) |
| Nutri-Score | алгоритм научного комитета, редакция 2022 (еда) и 2023 (напитки) |
| Нормы по сахару, соли, трансжирам | рекомендации ВОЗ |

Каждая запись о добавке ссылается на источник по ключу; ключи проверяются при
загрузке — приложение не стартует, если добавка ссылается на несуществующий источник.

**Как считается оценка.** Начинаем со 100 и вычитаем:

- добавки — до 45 баллов, взвешенно по уровню риска и по уверенности распознавания;
- светофоры по нутриентам — до 40 баллов;
- Nutri-Score сдвигает результат на ±12 (оценка по неполным данным — вдвое слабее);
- отдельные находки: трансжиры −25, пальмовое масло −4, короткий состав +6 и так далее.

Красный ставится, если есть добавка высокого риска, трансжиры, два «красных»
нутриента или итог ниже 40. Зелёный — от 75 при отсутствии добавок среднего и
высокого риска. Всё остальное — жёлтый.

## API

Полное описание — [`docs/api.md`](docs/api.md), развёртывание — [`docs/deployment.md`](docs/deployment.md). Кратко:

```
POST /api/v1/analyze/barcode   { barcode }
POST /api/v1/analyze/label     { text, barcode?, ocrConfidence? }
POST /api/v1/analyze/photo     { imageBase64 }
GET  /api/v1/additives?q=&risk=&category=
GET  /api/v1/additives/:code
GET  /api/v1/history · /stats · /:id      (POST /:id/favorite, DELETE /:id)
GET  /health
```

Тексты приходят уже переведёнными (`?locale=ru|en` или `Accept-Language`), поэтому
клиент остаётся тонким и новый язык не требует обновления приложения.

## Приватность

Аккаунтов нет. Устройство генерирует при первом запуске случайный `X-Device-Id` и
шлёт только его — ни почты, ни телефона, ни имени. История и избранное привязаны к
этому идентификатору, и один идентификатор не видит записи другого (это проверено
тестом). При OCR на устройстве фотография не покидает телефон.

## Ограничения — честно

- **Это не медицинский сервис.** Приложение объясняет состав, но не ставит диагнозов.
  При аллергии, беременности и хронических болезнях решает врач, а не светофор.
- **Оценки добавок опираются на позиции регуляторов** и датированы. По части веществ
  (каррагинан, эритрит, эмульгаторы и микрофлора) наука ещё не сошлась — в таких
  случаях в тексте так и написано, вместо выбора удобной стороны.
- **База добавок неполная.** 204 записи покрывают то, что реально встречается на
  упаковках, но не весь перечень E-номеров; неизвестные коды не выдумываются, а
  честно попадают в предупреждения. Оценки датированы — перед продакшном их стоит
  сверить с первоисточниками, см. [`backend/data/README.md`](backend/data/README.md).
- **OCR ошибается.** Движок чинит типовые ошибки (кириллическая «Е» в коде, цифры,
  прочитанные как буквы) и снижает уверенность для нечётких совпадений, но снимок
  под углом и в темноте по-прежнему читается плохо.
- **Nutri-Score для жиров, масел, орехов и семян** считается по общему профилю:
  для точного нужна доля калорий из жиров, которой на упаковке обычно нет. Такой
  результат помечается как приблизительный.
- **Open Food Facts заполняется сообществом.** Данные по конкретному товару могут
  быть неточными или устаревшими; если продукта нет, приложение предлагает
  сфотографировать состав.

## Разработка

```bash
cd backend && npm test          # движок и HTTP
cd backend && npm run typecheck
cd mobile  && npm run typecheck
```

Тесты не ходят в сеть: Open Food Facts подменяется заглушкой, база — `:memory:`.
Добавить добавку — это новая запись в одном из файлов `backend/data/additives/*.json`;
структура проверяется при загрузке, отдельного кода писать не нужно.

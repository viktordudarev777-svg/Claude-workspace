# Данные FoodLens

## Что здесь лежит

| Файл | Что внутри |
|---|---|
| `references.json` | Источники: EFSA, IARC, регламент ЕС 1333/2008, FDA, JECFA, ВОЗ, Codex |
| `additives/*.json` | Пищевые добавки, сгруппированные по назначению |
| `whole-foods.json` | Цельные продукты и блюда для распознавания по фотографии |

Файлы разбиты по группам намеренно: правку в 30 строк проще ревьюить, чем диф
в одном файле на несколько тысяч. Загрузчик читает каталог `additives/`
целиком, порядок файлов задаётся числовым префиксом.

## Как добавить добавку

Допишите запись в подходящий файл группы. Кода писать не нужно — загрузчик
подхватит её сам. Обязательные поля:

```jsonc
{
  "code": "E621",              // канонический вид: E + 3-4 цифры + необязательный суффикс
  "names": { "ru": "…", "en": "…" },
  "category": "flavour-enhancer",
  "risk": "moderate",          // none | low | moderate | high
  "summary": { "ru": "…", "en": "…" },   // одна строка для списка находок
  "detail":  { "ru": "…", "en": "…" },   // 2-4 предложения для экрана добавки
  "concerns": ["ultra-processed-marker"], // из закрытого списка ConcernTag
  "origin": "synthetic",       // synthetic | natural | mixed
  "adiMgPerKgBw": 30,          // null, если ADI не установлен
  "restrictedIn": [],          // коды стран или регионов
  "synonyms": ["глутамат натрия", "monosodium glutamate", "msg"],
  "sources": ["eu-1333-2008", "efsa-additives"]  // ключи из references.json
}
```

Проверить правку: `npm run validate-data`. Скрипт падает, если поле пропущено,
код записан не канонически, ссылка на источник не разрешается, текст слишком
короткий, чтобы что-то объяснить, синонимов нет вовсе или высокий риск заявлен
без единого тега `concerns`. Тот же скрипт гоняется в CI.

### О синонимах

Синонимы — это то, по чему добавка находится в тексте этикетки, когда код не
напечатан. Пишите все варианты, которые реально встречаются: русское и
английское название, торговые и устаревшие имена, индекс CL для красителей.

Если синоним совпадает с обычным ингредиентом или со словом из таблицы пищевой
ценности, добавьте его в `AMBIGUOUS_SYNONYMS` в `src/domain/additives/matcher.ts`.
Пример: E570 называется «жирные кислоты», и без этого списка строка «в том числе
насыщенные жирные кислоты» из таблицы БЖУ давала бы ложную находку. По коду
добавка при этом по-прежнему находится — на реальной этикетке она так и написана.

## Откуда взяты оценки и что с ними не так

Значения ADI, статусы разрешений и классификации взяты из позиций регуляторов:
EFSA (переоценка пищевых добавок), IARC (монографии), регламент (ЕС) 1333/2008,
FDA, JECFA. Каждая запись ссылается на источник ключом из `references.json`.

**Важные оговорки:**

- **Данные датированы.** Регуляторные оценки меняются: EFSA пересматривает
  добавки по программе, IARC публикует новые монографии, FDA отзывает
  разрешения. Перед выпуском в продакшн значения ADI и статусы запретов стоит
  сверить с первоисточниками заново.
- **Ссылки ведут на разделы, а не на конкретные заключения.** Мы указываем
  стабильные адреса (страница EFSA по добавкам, монографии IARC, консолидированный
  текст регламента), потому что прямые ссылки на отдельные документы часто
  протухают. Для аудита конкретного утверждения нужный документ придётся найти
  на сайте источника.
- **Там, где наука не сошлась, так и написано.** Каррагинан, эритрит,
  эмульгаторы и микрофлора кишечника — это открытые вопросы, и тексты
  сформулированы как открытые вопросы, а не как приговор в одну из сторон.
- **База неполная.** 204 записи покрывают то, что реально встречается на
  упаковках, но не весь перечень E-номеров. Неизвестный код не выдумывается:
  он попадает в `unknownCodes` и оттуда в предупреждения пользователю.

## Цельные продукты

`whole-foods.json` содержит типичный состав на 100 г съедобной части, округлённый
по открытым таблицам пищевой ценности (USDA FoodData Central и аналоги). Это
ориентир для случая «сфотографировал яблоко», а не паспорт конкретного плода:
реальные значения зависят от сорта, спелости и способа приготовления.
